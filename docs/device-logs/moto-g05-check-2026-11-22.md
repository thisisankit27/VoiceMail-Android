# Moto G05 mandatory compatibility check (2026-11-22)

This is the owner's **primary phone** and the intended target for the personal build. Every check was **read-only**: nothing was installed and no setting was changed. The default dialer is still Google Phone.

| Property | Value |
|---|---|
| Model / codename | moto g05 / `lamul` (product `lamul_gi`) |
| Android / SDK | 15 / 35 |
| SoC | MediaTek MT6769V/CB (Helio G81), `ro.board.platform=mt6768` |
| Radio | `dsds` (dual-SIM). No SIM inserted during the check |
| Default dialer | `com.google.android.dialer` |
| Wireless debugging | off (`adb_wifi_enabled=0`) |

## 1. The shell identity still holds the required permissions on Android 15
```text
$ adb shell dumpsys package com.android.shell
android.permission.CAPTURE_AUDIO_OUTPUT: granted=true
android.permission.MODIFY_PHONE_STATE: granted=true
android.permission.WRITE_SECURE_SETTINGS: granted=true
```

## 2. The MediaTek HAL exposes the path *into* the call (greeting)
```text
$ adb shell dumpsys media.audio_policy
"incall_music_uplink"; 0x10000 (AUDIO_OUTPUT_FLAG_INCALL_MUSIC)
IOProfile name:incall_music_uplink; Latency: 85
Port ID: 11; "Telephony Tx"; {AUDIO_DEVICE_OUT_TELEPHONY_TX, @:}
Selected Device: {AUDIO_DEVICE_OUT_TELEPHONY_TX, @:}
```

## 3. The MediaTek HAL exposes the path *from* the call (recording)
```text
Port ID: 17; "Voice Call In"; {AUDIO_DEVICE_IN_TELEPHONY_RX, @:}
```

## Verdict
The same architecture that worked on the G60 (Qualcomm), Option 4, is **structurally supported** on the G05 (MediaTek). The shell holds the permissions and both telephony audio paths exist. **Not yet tested on the G05:** an actual call (audio flow, `setMuted` with in-call music), the in-app wireless-debugging auto-start, and helper survival after Wi-Fi is lost. These are deferred until the app is ready for the G05.
